- Stop using generic clean 3D icons on a white background as the main direction.
- Every illustration must be in the same visual language as the old PDF report.
- Every illustration must be created for the exact slide context from `Taks Docs/Отчет длинная версия.docx`.

## Composition Rules

- Use a staged physical scene, not an isolated icon object.
- Build depth with foreground/midground/background layers.
- Use large rounded rectangular frames with thin mint outlines around hero scenes.
- Use dark negative space intentionally; do not fill every area.
- Add a small number of data/metric cards only when the source slide calls for them.
- Use glowing contour paths, rings, rails, edge lights, and transparent panels.
- Keep perspective cinematic: slightly elevated product-render angle, architectural scale, strong depth.
- Avoid toy-like proportions, cute clay icons, oversized padlocks, generic shields, and floating checklist cards unless the DOCX context directly demands that metaphor.

## Palette Rules

- Primary accent for this project: `#29CCB1` and close teal/mint variants.
- Use `#29CCB1` as an energetic glow, line, edge, route, rim, or key object color.
- Pair it with near-black and deep teal stage colors, not with a mostly empty white studio scene.
- Light pages may use `#F7F7F7` or white fields, but the illustration itself should still feel like the old report: premium, layered, glass/metal, cinematic.
- Purple/blue-violet may appear only as a restrained secondary glow, as in the PDF.

## Material Rules

- Preferred materials: matte black metal, dark glass, frosted acrylic, transparent green panels, polished plastic, luminous edges, fine grid surfaces.
- Preferred environments: dark product stage, futuristic lab/operations space, abstract control room, modular architecture, illuminated platform.
- Good motifs: glass rings, plinths, modular cubes, route contours, transparent dashboards, robotic/industrial objects, staged physical metaphors.
- Bad motifs: flat vector icons, stock cybersecurity dashboards, code rain, hacker hoodies, skulls, random padlocks, literal cloud icons, cartoon mascots.

## Slide-Context Rule

Before generating an illustration for any slide:

1. Read the exact DOCX section assigned to that slide.
2. Identify the slide's job and main idea without rewriting the text.
3. Choose a physical scene metaphor that fits that exact idea.
4. Generate in the old PDF style using `#29CCB1` as the dominant accent.
5. Reject the image if it could fit any generic cybersecurity slide.

For example, a slide titled `How to use the guide` should not be a generic shield/checklist/lock illustration. It should show the guide as a navigation/decision system: a staged route through checkpoints, a board-level decision path, or a physical operating model that implies using the report step by step.
